# Developer entry experiment

## Goal contract

**Goal:** give developers finding this repository a direct path to a hosted campaign check or a reviewable agent skill, without requiring them to deploy the scanner first.

**Context:** the repository previously led into self-hosting, while the hosted app already offered anonymous Basic checks and a public HTTP-downloadable skill. This change removes a distribution gap; it is not evidence that GitHub is a productive acquisition channel.

**In scope:** the README's hosted/agent entry paths, the four already-public generic skill assets, snapshot ownership/checksums, and GitHub-hosted documentation/install verification.

**Out of scope:** scanner or app runtime changes, new scan modes, pricing/auth changes, new telemetry, repository description/topics, registry submissions, outreach, SEO/indexing changes, and deployment. A prerequisite correction in the hosted skill's schema separates policy/terms fetching from the accepted-but-unfetched website URL; that belongs in the app repository and must merge before this snapshot.

**Done when:**
1. A reader can reach the hosted web scanner directly, or find and review all four agent skill files.
2. Copy describes anonymous Basic, paid authenticated calls, and URL-fetching scope accurately.
3. The install block preserves existing installations and the snapshot matches the corrected canonical skill.
4. GitHub-hosted verification is green for the exact PR head; independent review has no blocking findings.
5. The PR is open for Noah; no merge, deployment, settings update, or external promotion is performed by the agent.

**Verify with:** public GETs of the four skill assets (no API POSTs), byte comparisons with the canonical candidate, `git diff --check`, and the `Developer entry verification` GitHub Actions job. The job executes the exact documented install block in fresh temporary homes, verifies copied bytes, refuses repeat/symlink installs, checks checksums/relative reference targets, and parses the synthetic Basic example. No worker test suite is needed for this docs/assets-only change; no tests/builds/servers run on the Hermes VPS.

**Stop conditions:** incorrect or non-public source material, a request for credentials/customer data, failed verification or blocking review, or a change requiring runtime, spending, publication, or deployment approval. Stop implementation once the bounded PR and evidence are ready.

## Placement and measurement

The README's hosted CTA uses one generic campaign, not a personal identifier:

```
https://www.a2pcheck.com/10dlc-check?utm_source=github&utm_medium=referral&utm_campaign=developer_precheck
```

Start the observation window only after Noah merges the distribution PR. Record the merge date and review after 14 and 28 days. Do not treat this PR's existence as public distribution on the default branch.

For browser diagnostics, filter **both** `deployment:production` and `isQa:false`, plus `utmSource:github utmCampaign:developer_precheck`. Count `landing_view`, `form_started`, `scan_started`, and `scan_completed`; where present, use the existing same-tab `journeyId` to correlate steps rather than divide unrelated event totals. Current landing and first-touch source are distinct: inspect `landing` on landing/form events, not just `source`. A prior first-touch campaign can take precedence over this link, so these counts are not a complete GitHub referral census.

Labels are diagnostic, not proof of human/customer use. Browser events can be blocked, lost, duplicated, or generated by automation. Unknown storage history is deliberately excluded from the explicit non-QA cohort. A query returning zero immediately after deployment is not a pipeline failure.

Persisted scan attribution is a second signal: web scan attempts can retain the generic UTM campaign, while the existing growth summary's campaign buckets include **all statuses**. Do not call that bucket a successful-scan or customer count. The browser QA/deployment filter does not retroactively apply to commercial aggregates.

The agent/API path records only `origin:api`; it does not attribute executions to this repository or these UTMs. Public skill downloads have no download counter. Therefore installs, API calls, and paid conversion from the skill are **not measurable by channel today**. Do not add tracking solely to make this experiment appear measurable.

## Decision rules

- Tagged production/non-QA browser activity is a directional signal that the link is being used, not a causal lift or a unique-person count.
- Zero tagged activity without a reliable exposure denominator is inconclusive. GitHub views/clones cannot establish qualified human reach.
- A skill snapshot being published is an operational milestone, not acquisition success.
- At the review date, report counts and missing evidence honestly. Repeat or expand only if the observed use warrants it; do not turn an inconclusive result into a new instrumentation project.
- External listing submissions, repo settings changes, and community placements remain separate approval decisions. This PR authorizes none of them.
